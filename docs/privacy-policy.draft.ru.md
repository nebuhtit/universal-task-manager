# Universal Task Manager — проект политики конфиденциальности

Статус: **черновик для согласования, не опубликован**. Подготовлен 25 сентября 2026 года по текущему коду. Дата вступления в силу будет указана при публикации.

## 1. Приложение и контакт

Universal Task Manager — приложение для задач, календаря, напоминаний и учёта времени с преимущественно локальным хранением данных. Оно доступно как веб-приложение и приложение для iOS.

## 2. Данные на устройстве

Приложение сохраняет задачи, заметки, даты, повторения, историю, настройки и связанные данные в локальном хранилище браузера или приложения. Для основной работы отдельная регистрация на сервере разработчика не требуется.

В защищённом режиме содержимое workspace хранится зашифрованным. Режим без пароля не предоставляет такую же защиту. Часть служебных настроек, погодный кэш и диагностические журналы хранятся отдельно от зашифрованного workspace; шифрование workspace не означает шифрование всех данных приложения.

Разработчик не предоставляет восстановление забытого пароля workspace. Рекомендуется сохранять резервные копии и пароль в надёжном месте.

В iOS интерфейс загружается из файлов, включённых в приложение, а не с GitHub Pages. Дополнительные сетевые функции, описанные ниже, требуют подключения к интернету.

## 3. Подключение Google Calendar

Подключение добровольное. Авторизация выполняется через Google; приложение не получает пароль Google. Это разрешение на работу с календарём, а не создание серверной учётной записи Universal Task Manager.

При подключении приложение получает доступ к сведениям о календарях и событиях в пределах выданных разрешений. Для выбранных календарей оно использует названия, описания, местоположения, даты, время, повторения, занятость и идентификаторы событий для отображения, планирования и синхронизации. Полученные сведения сохраняются в локальном workspace/кэше.

Текущие разрешения:

- `calendar.readonly` — чтение календарей и событий;
- `calendar.events` — работа с событиями при использовании функций записи;
- `calendar.calendarlist.readonly` — чтение списка календарей для выбора назначения.

При разрешённой записи изменения связанных событий передаются в Google Calendar. Запросы выполняются с устройства к Google. Токены доступа используются для авторизации запросов и в текущей реализации хранятся в памяти на время сессии; они не включаются в обычный экспорт workspace.

Доступ можно отозвать в настройках подключений Google Account. Отзыв доступа прекращает возможность последующих авторизованных запросов, но сам по себе не удаляет уже сохранённые локальные копии или ранее изменённые события Google. Локальные данные и данные Google нужно удалять отдельно.

**Предлагаемое обязательство для утверждения владельцем:** использование информации, полученной через Google API, соответствует Google API Services User Data Policy, включая требования Limited Use. Эти данные используются только для пользовательских функций приложения; не продаются, не используются для рекламы, профилирования в рекламных целях или обучения обобщённых моделей ИИ. Доступ человека к таким данным допускается только в предусмотренных политикой Google случаях, например с явным согласием пользователя для поддержки. Это обязательство необходимо подтвердить перед публикацией, а не считать установленным одним просмотром кода.

## 4. Уведомления и будильники

На iOS локальные напоминания и таймеры передаются системным механизмам уведомлений и будильников после необходимых разрешений. Для этого не нужен сервер веб-уведомлений. Содержимое уведомления может быть видно на экране блокировки в соответствии с настройками iOS.

Отдельная функция фоновых веб-уведомлений использует сервер на Cloudflare и службу Push браузера. При её включении передаются идентификатор устройства, данные Push-подписки и задания напоминаний: время, идентификаторы, ссылка на item, важность и содержимое уведомления. В подробном режиме, который сейчас используется при включении, содержимое включает название задачи и сведения о её времени. Это не передача всего workspace, однако передаваемые сведения не защищены паролем workspace на сервере уведомлений.

Отключение веб-уведомлений отменяет будущие задания при успешном обращении к серверу. В текущей реализации оно **не удаляет все ранее сохранённые серверные записи**. Автоматический срок удаления отправленных и отменённых заданий пока не установлен в коде. До публичного запуска необходимо определить срок хранения и способ полного удаления; обещание немедленного удаления сейчас было бы неточным.

## 5. Погода и местоположение

Погода является дополнительной отключаемой функцией. Поиск места отправляет введённый запрос сервису геокодирования Open-Meteo. Получение прогноза отправляет координаты выбранного места в Open-Meteo. Название места, координаты и прогноз могут сохраняться локально вне зашифрованного workspace. Задачи для получения прогноза не требуются и не передаются этим запросом.

## 6. Резервные копии и экспорт

Пользователь выбирает, куда сохранить экспорт или резервную копию: локальные файлы, iCloud Drive либо другой доступный файловый сервис. Такой сервис получает выбранный файл и обрабатывает его по собственным правилам.

Зашифрованные копии `.utmb` защищены паролем. Незашифрованные форматы экспорта и диагностические файлы не следует считать защищёнными тем же паролем.

Экспорт workspace исключает импортированные Google-only события и настройки подключения Google. При этом собственные связанные задачи и сохранённые черновики/ожидающие операции записи могут оставаться в экспорте, включая текст и отдельные идентификаторы. Поэтому мы не обещаем, что любой экспорт не содержит вообще никаких сведений, связанных с Google.

Если автоматическое резервирование iCloud доступно и настроено в сборке, приложение сохраняет зашифрованную текущую и предыдущую копию в контейнере приложения. Ручное сохранение через «Файлы» работает отдельно. Удаление данных приложения не является удалением всех ранее экспортированных файлов или облачных копий.

## 7. Диагностика и поддержка

Приложение ведёт локальные ограниченные по объёму журналы ошибок, этапов запуска и медленных операций. В них могут быть версия приложения, время, длительность, категория операции и технические сведения об ошибке. Это отдельное локальное хранилище, не защищённое паролем workspace.

В проверенных путях диагностики не обнаружена автоматическая отправка этих журналов разработчику. Пользователь может экспортировать и самостоятельно отправить их для поддержки. Перед отправкой следует проверить содержимое и удалить ненужные личные сведения. **Срок хранения обращений и вложений у оператора необходимо согласовать отдельно.**

## 8. Сторонние сервисы

В зависимости от используемых функций сетевые запросы получают GitHub Pages (веб-сайт), Google (авторизация и календарь), Open-Meteo (погода), Cloudflare и службы Push (фоновые веб-уведомления), Apple и выбранные файловые провайдеры (системные функции и облачные копии).

При сетевом соединении поставщик может получать IP-адрес и технические сведения запроса. Его обработка и инфраструктурные журналы регулируются также правилами соответствующего поставщика. Локальный характер workspace не означает отсутствие любых сетевых запросов.

## 9. Управление данными

Пользователь может отключить дополнительные функции, отозвать разрешения Google и iOS, экспортировать данные и удалить локальные данные приложения/сайта. Перед очисткой рекомендуется сделать проверенную резервную копию. Очистка локального хранилища необратима без копии и не отменяет автоматически сохранённые данные у сторонних сервисов.

Экспорты и резервные копии удаляются отдельно в выбранном файловом сервисе. Запросы о данных, действительно полученных оператором приложения, можно направлять по подтверждённому контактному адресу. Оператор не может дистанционно извлечь или восстановить локальный зашифрованный workspace только по такому обращению.
