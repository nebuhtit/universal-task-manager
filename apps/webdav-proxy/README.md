# UTM WebDAV HTTPS proxy

Separate Cloudflare Worker for browsers whose WebDAV server cannot enable CORS. Native iOS keeps its direct connection. No database, file storage, credentials or workspace encryption keys are configured in this Worker. The Basic WebDAV credentials pass through it in memory over HTTPS, so use an operator you trust.

Set `ALLOWED_ORIGINS` to exact trusted application origins and `UPSTREAM_BASES` to comma-separated trusted HTTPS WebDAV base URLs with trailing slashes. The checked-in configuration permits the user's Keenetic WebDAV only. Other users can deploy their own instance with their server configured; this is not an arbitrary public proxy. Do not allow localhost, private IPs or internal-service domains as upstreams.

Deploy from this directory using `pnpm dlx wrangler deploy`. Enter the resulting `https://…workers.dev/dav` URL in UTM's HTTPS proxy field (sign-in or Settings → WebDAV). Leave the WebDAV server URL and credentials unchanged. Leave proxy empty for direct access. The proxy address is stored with device-local encrypted connection settings.

The relay preserves HTTP status, ETag, If-Match, If-None-Match, LOCK/UNLOCK tokens, finite lock timeout and MOVE destination/Overwrite. It refuses redirects and paths outside configured servers. CORS preflight is answered locally. Request and response payloads are bounded to 20 MiB; a 20-second deadline covers upload, upstream response headers and the entire response body, shorter than the client's 30-second deadline. Unknown-outcome writes are never replayed by the relay.

Development runtime observability is enabled in `wrangler.jsonc` and can be disabled there. Custom structured reports contain only version, validated request ID, method, stage, status, byte counts and timing. Stages are `received`, `request-body`, `upstream-headers`, `upstream-body`, `complete`; preflight and health requests have their own stages. Never log headers, bodies, upstream addresses, authorization, lock tokens or exception text. Cloudflare infrastructure logs have provider-controlled access and retention, separate from device diagnostics.

`GET /health` from an allowed app Origin checks only that the relay is reachable; it does not check WebDAV credentials or the upstream server. CORS-exposed `X-UTM-Relay-*` response headers report request ID, deployed relay version, final stage and duration. Browser requests send the same UUID used in the local journal, enabling correlation in Cloudflare Workers Logs or `wrangler tail`. `X-UTM-WebDAV-Error` distinguishes an upstream timeout/network failure, an unconfigured target, a redirect and an oversized payload. A browser timeout without these headers does not prove the request reached the Worker. Inspect the server report for that UUID; absence from retained logs is not proof that it never arrived.

Verification: `pnpm exec vitest run apps/webdav-proxy/src/index.test.ts apps/web/src/services/webdavSync.test.ts` from the repository root. After deployment, verify OPTIONS plus an authenticated read before testing sync with disposable data.
