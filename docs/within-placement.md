# Live Text: items inside time blocks

Type `rr wo` or `рр wo` and select Work. Repeat to select another block. The input shows selected relations as removable name chips; technical IDs are hidden. Stored capture source uses `rr [Work](item:ID)`; names are labels and encoded IDs are authoritative. Editing visible text retains the selected IDs and selection order. Numeric `rr` alarm input retains its existing meaning. Ordinary relations are unchanged.

`scheduled_within` relations retain selection order. Placement uses the blocks' shared interval, falling back to the first available selected block. Tasks without explicit times are queued by creation time and ID. Explicit start/end values remain authoritative. A new undated capture chooses the first target's next/current occurrence (searched up to a year ahead) and saves its planned day; `utm:withinNotBefore` prevents placing that capture before its creation time. If no occurrence is found, the task remains undated.

Once a planned day is in the past in the workspace timezone, an open task without explicit UTM/Google start/end is displayed in the first selected block's current or next occurrence (up to a year ahead). A current block is still eligible until its end; placement starts at the block's beginning and follows the existing creation-order queue. Today and future planned days, closed tasks and explicit times do not roll over. Without an upcoming block the original day remains. This never overwrites the stored planned date or creates a Google event. Snapshot caches expire at local midnight and relevant block endings, not on every clock tick. Calendar, statistics and preview pass the same reference clock into the shared placement function.

`withinPlacementWorkspace` is a **read-only presentation projection**, shared by calendar evaluation, Timeline and View statistics. Never persist its schedules or send them to Google. Editor entry resolves the stored original by ID. The preview uses the same projection. Reserved intervals and task intervals use existing union-based capacity accounting. The original item's estimate remains unchanged.

Caches require immutable workspace snapshots, like existing calendar caches. Weak snapshot caching and bounded block/day caches reuse unaffected placements. Changes to linked blocks (including recurrence), task schedule/duration/relations or deletions invalidate the relevant inputs. Unrelated relationships do not participate. Repeating block instances are projected; source records are not materialized or modified.
